Set up your own Firebase sync

CuePoint keeps all bookmarks locally on your device by default with no account. Follow these five steps if you want timestamps and notes to sync live across Firefox desktop and Android using your own free Firebase project.

Create a dedicated Firebase project

  1. 1. Open the Firebase Console and sign in with your Google account.
  2. 2. Select Add project (or Create a project) and give it a clear name such as cuepoint-personal.
  3. 3. Skip optional extras like Google Analytics, confirm you stay on the free Spark plan ($0, no billing card required), and select Create project.

Keep this project selected through Step 5. Your web API key, database URL, and sync user must all come from this same dedicated project so its database rules never affect another app.

Enable Email/Password and create your sync user

  1. 1. In the left sidebar, open Build → Authentication → Sign-in method (select Get started first if prompted).
  2. 2. Select Email/Password, turn on the first Email/Password switch, and click Save. Leave Email link (passwordless) turned off.
  3. 3. Open the Users tab, select Add user, and enter an email address and a strong, unique password for CuePoint.

Do not reuse your Google account password. Save this Firebase password in your password manager and sign in with the same Firebase user on every device that should share one library.

Create a Realtime Database in Locked mode

  1. 1. Open Build → Realtime Database and select Create Database.
  2. 2. Choose a region near you, select Start in locked mode, and finish creating the database.
  3. 3. On Realtime Database → Data, copy the root HTTPS database URL shown above the tree.
Expected root URL shape
https://your-project-default-rtdb.firebaseio.com// US default
https://your-project-default-rtdb.europe-west1.firebasedatabase.app// Regional

Use Realtime Database, not Cloud Firestore. Do not choose Test mode or open public rules; the locked database is expected to deny access until you publish Step 4’s rules.

Publish CuePoint’s Security Rules

  1. 1. Open Realtime Database → Rules on the database you just created.
  2. 2. Replace the entire default Locked-mode JSON with the rules below, then select Publish.
Realtime Database → Rules (JSON) 

          


          

            

              
auth.uid == $uid

              
Only your signed-in Firebase user can read or write records under /users/<uid>.

            

            

              
.validate on cuepointV2/videos

              
Verifies matching videoId and numeric revision on every write.

Common questions & troubleshooting

          

            

              
                Config says apiKey detected, but databaseURL is missing
                
              
              

                Firebase sometimes omits databaseURL when the web app was registered before the Realtime Database
                was created. Paste the snippet into CuePoint anyway, then copy your root URL from
                Realtime Database → Data into the Realtime Database URL
                field that appears below it.
              

            

            

              
                HTTP 401 / 403 or “Permission denied” when connecting
                
              
              

                Confirm you clicked Publish in Realtime Database → Rules
                on the exact database matching your URL, and that your API key, database URL, and Authentication user all
                belong to the same Firebase project. Never switch rules to public/test mode to fix a connection error.
              

            

            

              
                Invalid email or password / Email/Password sign-in not enabled
                
              
              

                Confirm the standard Email/Password switch (not just email link) is enabled under
                Authentication → Sign-in method, and that you are entering the Firebase user
                created in Step 2—not your Google account password.
              

            

            

              
                Two devices are connected, but show different bookmarks
                
              
              

                Check that both devices are in Cloud (BYOC) mode, connected to the same
                Database URL, and signed in with the same Account email. Bookmarks saved
                while in Local mode stay local until you use Copy Local Moments.
              

            

            

              
                The database looks empty in Firebase Console after signing in
                
              
              

                Normal for a new account. The users/<uid>/cuepointV2/videos tree is created automatically
                the first time you save a moment in Cloud mode or run Copy Local Moments.
